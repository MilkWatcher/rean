#1 · Easy · Hash map lookup

Two Sum

In plain words

You get a list of numbers and a target. Find the two positions whose numbers add up to the target, and return those two positions. Example: nums = [2, 7, 11, 15], target = 9 → [0, 1], because nums[0] + nums[1] = 2 + 7 = 9.

How to think about it

The slow way checks every pair: for each number, loop over all the others. That is two loops, O(n²). The trick: when you are standing on a number x, you already know the partner you need: target − x. So keep a hash map of every number you have already passed (number → its position). For each new number, ask the map: "have I seen my partner?" Asking a hash map is instant, so the whole thing is one loop.

Steps

  1. Make an empty map: seen, from number to index.
  2. Go through the list once. For the number at position i, work out need = target − nums[i].
  3. If need is in the map, you're done: return {map[need], i}.
  4. Otherwise, store this number: map[nums[i]] = i, and move on.

The code

class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        // seen[value] = the index where we saw that value
        unordered_map<int, int> seen;

        for (int i = 0; i < (int)nums.size(); i++) {
            // The number that would pair with nums[i] to hit target
            int need = target - nums[i];

            // .count(key) is 1 if the key is in the map, 0 if not
            if (seen.count(need)) {
                return {seen[need], i};   // {} builds a vector<int>
            }

            // Not found yet: remember this number for later ones
            seen[nums[i]] = i;
        }
        return {};   // the problem promises an answer, so never reached
    }
};

  • Use seen.count(need) to check. Writing seen[need] on a missing key silently inserts it with value 0.
#2 · Easy · Hash set

Contains Duplicate

In plain words

Return true if any number appears at least twice in the list, and false if every number is different. Example: [1, 2, 3, 1] → true.

How to think about it

Walk through the list and keep a set of numbers you've already seen. A set is like a map with only keys: it answers "is x in here?" instantly. The moment you meet a number that's already in the set, you've found a duplicate.

Steps

  1. Make an empty unordered_set<int>.
  2. For each number: if it's already in the set, return true.
  3. Otherwise insert it.
  4. If the loop finishes, there were no repeats: return false.

The code

class Solution {
public:
    bool containsDuplicate(vector<int>& nums) {
        unordered_set<int> seen;          // numbers we've passed so far

        for (int x : nums) {              // x takes each value in turn
            if (seen.count(x)) {          // already seen it?
                return true;              // that's a duplicate
            }
            seen.insert(x);               // remember it
        }
        return false;                     // got to the end: all different
    }
};

How fast

Time O(n), space O(n).

Watch out

  • Another valid way: sort the list, then check if any two neighbours are equal. That's O(n log n) but uses no extra set.
#3 · Easy · Counting

Valid Anagram

In plain words

Two words are anagrams if they use exactly the same letters the same number of times, just in a different order. Return true if t is an anagram of s. Example: "anagram" and "nagaram" → true; "rat" and "car" → false. Only lowercase a–z.

How to think about it

Count the letters. Because there are only 26 lowercase letters, an array of 26 ints is enough: slot 0 for 'a', slot 1 for 'b', and so on. Add 1 for each letter in s and subtract 1 for each letter in t. If they are anagrams, every slot ends at 0.

Steps

  1. If the lengths differ, return false straight away.
  2. Make int count[26] = {0}.
  3. For each char c in s: count[c - 'a']++. For each char in t: count[c - 'a']--.
  4. If any slot is not 0, return false. Otherwise true.

The code

class Solution {
public:
    bool isAnagram(string s, string t) {
        if (s.size() != t.size()) return false;   // different lengths: no

        int count[26] = {0};       // one counter per letter, all start at 0

        // c - 'a' turns a letter into 0..25 ('a'->0, 'b'->1, ... 'z'->25)
        for (char c : s) count[c - 'a']++;
        for (char c : t) count[c - 'a']--;

        for (int i = 0; i < 26; i++) {
            if (count[i] != 0) return false;      // some letter didn't match
        }
        return true;
    }
};

How fast

Time O(n). Space O(1): the array is always 26 slots, however long the words are.

Watch out

  • c - 'a' works because chars are stored as numbers and 'a' to 'z' are consecutive.
  • If the input could contain any characters (not just a–z), use an unordered_map<char, int> instead of the array.
#4 · Medium · Hash map with a built key

Group Anagrams

In plain words

Given a list of words, put the anagrams together in groups. Example: ["eat","tea","tan","ate","nat","bat"] → [["eat","tea","ate"], ["tan","nat"], ["bat"]]. The groups can be in any order.

How to think about it

Anagrams look identical once you sort their letters: "eat", "tea" and "ate" all become "aet". So use the sorted word as a key in a map, and the value is the list of original words that share that key. At the end, every value in the map is one group.

Steps

  1. Make unordered_map<string, vector<string>> groups.
  2. For each word: copy it, sort the copy, and push the original word into groups[sortedCopy].
  3. Move every value from the map into the answer.

The code

class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        // key: the word with its letters sorted ("aet")
        // value: every original word with that key ("eat", "tea", "ate")
        unordered_map<string, vector<string>> groups;

        for (const string& word : strs) {   // const& = read it, don't copy
            string key = word;              // make a copy we can change
            sort(key.begin(), key.end());   // "tea" -> "aet"
            groups[key].push_back(word);    // [] creates an empty list if new
        }

        vector<vector<string>> answer;
        // Each map entry is a pair: .first is the key, .second the list
        for (auto& entry : groups) {
            answer.push_back(entry.second);
        }
        return answer;
    }
};

How fast

Time O(n · k log k), where n is the number of words and k the longest word (sorting each word). Space O(n · k).

Watch out

  • Here using groups[key] on a new key is exactly what you want: it creates an empty vector you can push into.
  • Faster key for long words: count the 26 letters and turn the counts into a string. Sorting is fine for interviews.
#5 · Medium · Count, then pick the biggest

Top K Frequent Elements

In plain words

Return the k numbers that appear most often. Example: nums = [1,1,1,2,2,3], k = 2 → [1, 2] (1 appears 3 times, 2 appears twice). Any order is fine.

How to think about it

Two steps. First count how often each number appears (a map from number to count). Then you need the k numbers with the highest counts. The simplest correct way: copy the (count, number) pairs into a vector, sort it from biggest count to smallest, and take the first k. The follow-up asks for better than O(n log n); the bucket version for that is under "Watch out".

Steps

  1. Count: freq[x]++ for every x.
  2. Copy each (count, number) into a vector of pairs.
  3. Sort the pairs in descending order. Pairs sort by .first (the count) first.
  4. Take the .second (the number) of the first k pairs.

The code

class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        // 1. Count how many times each number appears
        unordered_map<int, int> freq;
        for (int x : nums) freq[x]++;      // missing keys start at 0

        // 2. Put (count, number) pairs in a list so we can sort them
        vector<pair<int, int>> byCount;
        for (auto& [number, count] : freq) {   // unpack each map entry
            byCount.push_back({count, number});
        }

        // 3. Sort biggest count first (greater<> means descending)
        sort(byCount.begin(), byCount.end(), greater<pair<int, int>>());

        // 4. The first k pairs are the answer; keep just the numbers
        vector<int> answer;
        for (int i = 0; i < k; i++) {
            answer.push_back(byCount[i].second);
        }
        return answer;
    }
};

How fast

Time O(n log n) because of the sort. Space O(n).

Watch out

  • auto& [number, count] : freq unpacks each map entry into two names (C++17). It's the same as entry.first and entry.second.
  • Faster O(n) version (bucket sort): make vector<vector<int>> bucket(n + 1), put each number into bucket[its count], then walk the buckets from n down to 1, collecting numbers until you have k.
#6 · Medium · Sliding window

Longest Substring Without Repeating Characters

In plain words

Find the length of the longest stretch of the string (letters next to each other) where no character repeats. Example: "abcabcbb" → 3 ("abc"). "pwwkew" → 3 ("wke").

How to think about it

Picture a window over the string with a left edge and a right edge. Move right forward one character at a time. If the new character already appears inside the window, the window is broken, so jump left to just past that earlier copy. To know where the earlier copy was, keep a map from character to the last index where you saw it. After each step, the window right − left + 1 has no repeats, so compare its size to the best so far.

Steps

  1. left = 0, best = 0, and a map last from char to last index seen.
  2. For right = 0 to the end: let c = s[right].
  3. If c was seen before and that index is inside the window (≥ left), move left to last[c] + 1.
  4. Record last[c] = right, then best = max(best, right − left + 1).

The code

class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        unordered_map<char, int> last;   // char -> last index we saw it at
        int best = 0;
        int left = 0;                    // window is s[left .. right]

        for (int right = 0; right < (int)s.size(); right++) {
            char c = s[right];

            // Seen c before, and that copy is inside the current window?
            if (last.count(c) && last[c] >= left) {
                left = last[c] + 1;      // move left just past the old copy
            }

            last[c] = right;             // c's newest position
            best = max(best, right - left + 1);   // window length
        }
        return best;
    }
};

Time O(n): right moves n times and left only ever moves forward. Space O(number of different characters).

  • The check last[c] >= left matters. In "abba", when right reaches the last 'a', the old 'a' at index 0 is already outside the window (left is 2), so left must not jump back.
  • Window length is right − left + 1, not right − left.
#7 · Medium · Hash set · Mini-test 1

Longest Consecutive Sequence

In plain words

Given an unsorted list, find the length of the longest run of consecutive numbers (like 1, 2, 3, 4), in any order in the list. Must be O(n). Example: [100, 4, 200, 1, 3, 2] → 4 (the run 1, 2, 3, 4).

Do this one timed. Open one hint, try again, then open the next.

Hint 1

Sorting would be O(n log n), which isn't allowed. What container lets you ask "is x + 1 in the list?" instantly?

Hint 2

Put every number in an unordered_set. Now, from any number x you can count upward: x+1, x+2, ... while they're in the set.

Hint 3

That could still be slow if you count up from every number. Only start counting from x if x − 1 is not in the set, which means x is the start of a run.

Show the full walkthrough

How to think about it

Put everything in a set. A number x is the start of a run only if x − 1 isn't in the set. From each start, count upward while the next number exists. Each number is counted once in total, so it's O(n).

The code

class Solution {
public:
    int longestConsecutive(vector<int>& nums) {
        // Put every number in a set so "is x in the list?" is O(1)
        unordered_set<int> have(nums.begin(), nums.end());
        int best = 0;

        for (int x : have) {
            // Only start counting at the beginning of a run
            if (have.count(x - 1)) continue;   // x-1 exists: not a start

            int length = 1;
            while (have.count(x + length)) {   // x+1, x+2, ... present?
                length++;
            }
            best = max(best, length);
        }
        return best;
    }
};

How fast

Time O(n): each number is looked at a constant number of times. Space O(n).

Watch out

  • Loop over the set, not the original list, so duplicates don't make you repeat work.
  • An empty list must return 0. Here it does, because best starts at 0.
#8 · Easy · Counting + reading input · Mini-test 1

Frequency Leader (custom)

In plain words

Read n, then n integers from the input. Print the value that appears most often. If several values tie, print the smallest of them. Example: input "7" then "4 1 4 2 1 4 1" → 1 (1 and 4 both appear 3 times; 1 is smaller).

Do this one timed. Open one hint, try again, then open the next.

Hint 1

There's no function here: you write the whole program, including main() and reading with cin. Use the input template from the cram notes.

Hint 2

Count with unordered_map<int, int>, the same as Top K Frequent.

Hint 3

Then scan the map with two variables, bestValue and bestCount. A value wins if its count is bigger, or the count is equal and the value is smaller.

Show the full walkthrough

How to think about it

Read all the numbers and count them in a map. Then go through the map keeping the best answer so far, with the tie rule built into the comparison.

The code

#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);   // makes cin fast for big inputs
    cin.tie(nullptr);

    int n;
    cin >> n;                      // first number: how many follow

    unordered_map<long long, int> freq;
    for (int i = 0; i < n; i++) {
        long long x;
        cin >> x;
        freq[x]++;
    }

    long long bestValue = 0;
    int bestCount = 0;
    for (auto& [value, count] : freq) {
        // Better if more frequent, or same count but smaller value
        if (count > bestCount || (count == bestCount && value < bestValue)) {
            bestValue = value;
            bestCount = count;
        }
    }
    cout << bestValue << '\n';
    return 0;
}

How fast

Time O(n), space O(number of different values).

Watch out

  • Values can be negative. Starting bestValue at 0 is still safe, because bestCount starts at 0 and the first real value always replaces it.
  • Values reach ±10⁹, which fits in an int; long long is used here just to be safe.
  • Print with '\n' at the end. Some judges are strict about the final newline.

#9 · Easy · DFS on a grid (recursion)

Flood Fill

In plain words

A picture is a grid of numbers (colours). Starting at cell (sr, sc), change that cell and every cell connected to it (up, down, left, right) that has the same original colour to the new colour. Like the paint-bucket tool in Paint.

How to think about it

This is your first grid search. From the start cell, paint it, then do the same thing to each of its 4 neighbours, but only if the neighbour is inside the grid and still has the original colour. A function that calls itself on the neighbours (recursion, also called DFS: depth-first search) does exactly this.

Steps

  1. Remember the original colour of the start cell.
  2. If it's already the new colour, return the image unchanged (otherwise you'd loop forever).
  3. Write a helper fill(r, c): if (r, c) is off the grid or not the original colour, stop. Otherwise paint it and call fill on the 4 neighbours.
  4. Call fill(sr, sc) and return the image.

The code

class Solution {
public:
    vector<vector<int>> floodFill(vector<vector<int>>& image,
                                  int sr, int sc, int color) {
        int original = image[sr][sc];
        if (original == color) return image;   // nothing to do (and avoids
                                               // painting forever)
        fill(image, sr, sc, original, color);
        return image;
    }

private:
    // Paint (r, c) and spread to neighbours with the same original colour
    void fill(vector<vector<int>>& img, int r, int c, int original, int color) {
        // Stop if we stepped off the grid
        if (r < 0 || r >= (int)img.size() || c < 0 || c >= (int)img[0].size())
            return;
        // Stop if this cell isn't part of the region
        if (img[r][c] != original) return;

        img[r][c] = color;          // paint it (also marks it as visited)

        fill(img, r + 1, c, original, color);   // down
        fill(img, r - 1, c, original, color);   // up
        fill(img, r, c + 1, original, color);   // right
        fill(img, r, c - 1, original, color);   // left
    }
};

How fast

Time O(rows × cols): each cell is painted at most once. Space O(rows × cols) in the worst case for the recursion.

Watch out

  • Painting a cell is what stops it being visited twice: once it's the new colour, it no longer matches original.
  • Always check the grid edges before reading img[r][c], or you read outside the vector and crash.
#10 · Medium · Count connected regions

Number of Islands

In plain words

The grid has '1' for land and '0' for water. An island is a group of land cells joined up, down, left or right. Count the islands.

How to think about it

Scan every cell. When you find land you haven't visited, that's a new island: add 1, then "sink" the whole island (turn all its connected land into water) with the same recursion as Flood Fill, so you never count it again.

Steps

  1. count = 0. Loop over every row r and column c.
  2. If grid[r][c] is '1': count++, then sink(r, c).
  3. sink(r, c): if off the grid or not '1', stop. Otherwise set it to '0' and sink the 4 neighbours.
  4. Return count.

The code

class Solution {
public:
    int numIslands(vector<vector<char>>& grid) {
        int count = 0;
        for (int r = 0; r < (int)grid.size(); r++) {
            for (int c = 0; c < (int)grid[0].size(); c++) {
                if (grid[r][c] == '1') {   // land we haven't sunk yet
                    count++;               // so it's a new island
                    sink(grid, r, c);      // remove the whole island
                }
            }
        }
        return count;
    }

private:
    // Turn this land cell and all land connected to it into water
    void sink(vector<vector<char>>& g, int r, int c) {
        if (r < 0 || r >= (int)g.size() || c < 0 || c >= (int)g[0].size())
            return;                        // off the grid
        if (g[r][c] != '1') return;        // water, or already sunk

        g[r][c] = '0';                     // sink it = mark visited
        sink(g, r + 1, c);
        sink(g, r - 1, c);
        sink(g, r, c + 1);
        sink(g, r, c - 1);
    }
};

How fast

Time O(rows × cols). Space O(rows × cols) worst case for recursion.

Watch out

  • The grid holds chars: compare with '1' (quotes), not the number 1.
  • If the interviewer doesn't want you to change the input, keep a separate vector<vector<bool>> visited instead.
  • On a very large grid, recursion can overflow the stack. Then use the BFS template from the cram notes (a queue instead of recursion).
#11 · Medium · DFS that returns a count

Max Area of Island

In plain words

Same grid idea, but with ints 1 and 0. The area of an island is how many cells it has. Return the biggest area, or 0 if there's no land.

How to think about it

Exactly Number of Islands, except the sink function now returns how many cells it sank: 1 for this cell plus whatever its 4 neighbours return. Keep the maximum.

Steps

  1. For each land cell, call area(r, c) and keep the biggest result.
  2. area(r, c): off the grid or water → return 0.
  3. Otherwise mark it 0, and return 1 + area of the 4 neighbours.

The code

class Solution {
public:
    int maxAreaOfIsland(vector<vector<int>>& grid) {
        int best = 0;
        for (int r = 0; r < (int)grid.size(); r++)
            for (int c = 0; c < (int)grid[0].size(); c++)
                if (grid[r][c] == 1)
                    best = max(best, area(grid, r, c));
        return best;
    }

private:
    // Sink the island at (r, c) and return how many cells it had
    int area(vector<vector<int>>& g, int r, int c) {
        if (r < 0 || r >= (int)g.size() || c < 0 || c >= (int)g[0].size())
            return 0;                  // off the grid adds nothing
        if (g[r][c] != 1) return 0;    // water or visited adds nothing

        g[r][c] = 0;                   // mark visited
        return 1                       // this cell
             + area(g, r + 1, c) + area(g, r - 1, c)
             + area(g, r, c + 1) + area(g, r, c - 1);
    }
};

How fast

Time O(rows × cols), space O(rows × cols) worst case.

Watch out

  • This is the general trick for grid recursion: decide what each call returns, and what it returns for the "stop" cases (here 0).
#12 · Medium · Multi-source BFS (spreading by minutes)

Rotting Oranges

In plain words

Each cell is 0 (empty), 1 (fresh orange) or 2 (rotten). Every minute, each rotten orange rots its fresh neighbours (up, down, left, right). Return how many minutes until no fresh orange is left, or −1 if some can never rot.

How to think about it

Rot spreads in waves, one step per minute. That's breadth-first search (BFS): a queue processes cells in the order they were reached, so it naturally goes wave by wave. Put all rotten oranges in the queue at the start (several starting points = "multi-source"). Each minute, process exactly the cells currently in the queue, rot their fresh neighbours and add those to the queue.

Steps

  1. Scan the grid: push every rotten orange's position into a queue, and count the fresh ones.
  2. minutes = 0. While the queue isn't empty and fresh > 0: process one wave (the current queue size), rotting fresh neighbours, then minutes++.
  3. At the end: if fresh is still > 0, return −1. Otherwise return minutes.

The code

class Solution {
public:
    int orangesRotting(vector<vector<int>>& grid) {
        int R = grid.size(), C = grid[0].size();
        queue<pair<int, int>> q;   // positions of rotten oranges to spread from
        int fresh = 0;

        for (int r = 0; r < R; r++)
            for (int c = 0; c < C; c++) {
                if (grid[r][c] == 2) q.push({r, c});   // all starting points
                else if (grid[r][c] == 1) fresh++;
            }

        // The 4 directions as (row change, column change)
        int dr[4] = {1, -1, 0, 0};
        int dc[4] = {0, 0, 1, -1};
        int minutes = 0;

        while (!q.empty() && fresh > 0) {
            int waveSize = q.size();          // everything rotten right now
            for (int i = 0; i < waveSize; i++) {
                auto [r, c] = q.front();      // take the next rotten orange
                q.pop();
                for (int d = 0; d < 4; d++) {
                    int nr = r + dr[d], nc = c + dc[d];
                    if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
                    if (grid[nr][nc] != 1) continue;   // only fresh ones rot
                    grid[nr][nc] = 2;         // rot it now so it's not
                    fresh--;                  // counted twice
                    q.push({nr, nc});         // it spreads next minute
                }
            }
            minutes++;                        // one whole wave = one minute
        }
        return fresh == 0 ? minutes : -1;
    }
};

How fast

Time O(rows × cols): each orange enters the queue once. Space O(rows × cols) for the queue.

Watch out

  • Mark a neighbour rotten when you push it, not when you pop it. Otherwise two oranges can both push it, and it's counted twice.
  • The loop also stops when fresh hits 0, so you don't add an extra minute at the end.
  • No fresh oranges at the start → answer 0.
#13 · Medium · BFS for shortest path

Shortest Path in Binary Matrix

In plain words

An n × n grid of 0s (open) and 1s (blocked). Find the shortest path from the top-left to the bottom-right through open cells, moving in any of 8 directions (diagonals too). The length counts cells, including the first and last. Return −1 if there's no path.

How to think about it

When every step costs the same, BFS finds the shortest path: it explores everything 1 step away, then 2 steps, and so on, so the first time it reaches a cell is the shortest way there. Store the distance to each cell in a dist grid, which also tells you which cells you've already visited (−1 = not yet).

Steps

  1. If the start or end is blocked, return −1.
  2. dist = n × n grid of −1. Set dist[0][0] = 1 and push (0, 0).
  3. Pop a cell; for each of the 8 neighbours that's inside, open (0) and unvisited: dist = current + 1, push it.
  4. Return dist[n−1][n−1] (still −1 if never reached).

The code

class Solution {
public:
    int shortestPathBinaryMatrix(vector<vector<int>>& grid) {
        int n = grid.size();
        if (grid[0][0] == 1 || grid[n - 1][n - 1] == 1) return -1;

        // dist[r][c] = path length to reach (r, c); -1 means not visited
        vector<vector<int>> dist(n, vector<int>(n, -1));
        queue<pair<int, int>> q;
        dist[0][0] = 1;            // the start cell counts as length 1
        q.push({0, 0});

        while (!q.empty()) {
            auto [r, c] = q.front();
            q.pop();
            // Try all 8 neighbours: every dr and dc from -1 to 1
            for (int dr = -1; dr <= 1; dr++) {
                for (int dc = -1; dc <= 1; dc++) {
                    if (dr == 0 && dc == 0) continue;     // that's itself
                    int nr = r + dr, nc = c + dc;
                    if (nr < 0 || nr >= n || nc < 0 || nc >= n) continue;
                    if (grid[nr][nc] == 1) continue;      // blocked
                    if (dist[nr][nc] != -1) continue;     // already visited
                    dist[nr][nc] = dist[r][c] + 1;
                    q.push({nr, nc});
                }
            }
        }
        return dist[n - 1][n - 1];
    }
};

How fast

Time O(n²): each cell is visited once. Space O(n²).

Watch out

  • Use BFS (a queue), not DFS, for shortest paths. DFS finds a path, not the shortest.
  • A 1 × 1 grid [[0]] has answer 1.

Find if Path Exists in Graph

In plain words

There are n points (nodes) numbered 0 to n−1, and a list of two-way connections (edges) like [0, 1]. Return true if you can get from source to destination by following edges.

Do this one timed. Open one hint, try again, then open the next.

Hint 1

First turn the edge list into an adjacency list: vector<vector<int>> adj(n), where adj[a] lists every node connected to a. Each edge goes in both directions.

Hint 2

Then it's a search from source, just like the grid, but the "neighbours" of u are adj[u] instead of 4 directions.

Hint 3

Keep a vector<bool> visited(n) so you don't loop forever around a cycle.

Show the full walkthrough

How to think about it

Build the adjacency list, then BFS from source. If you ever pop destination, return true. If the queue empties first, return false.

The code

class Solution {
public:
    bool validPath(int n, vector<vector<int>>& edges,
                   int source, int destination) {
        // adj[u] = every node directly connected to u
        vector<vector<int>> adj(n);
        for (auto& e : edges) {
            adj[e[0]].push_back(e[1]);   // edges go both ways
            adj[e[1]].push_back(e[0]);
        }

        vector<bool> visited(n, false);
        queue<int> q;
        q.push(source);
        visited[source] = true;

        while (!q.empty()) {
            int u = q.front();
            q.pop();
            if (u == destination) return true;    // reached it
            for (int v : adj[u]) {                // every neighbour of u
                if (!visited[v]) {
                    visited[v] = true;
                    q.push(v);
                }
            }
        }
        return false;                             // ran out of places to go
    }
};

How fast

Time O(n + number of edges). Space O(n + number of edges).

Watch out

  • Forgetting the second push_back makes the graph one-way and gives wrong answers.
  • source == destination is true straight away (the first pop).
#15 · Medium · Topological sort (cycle check) · Mini-test 2

Course Schedule

In plain words

There are numCourses courses. Each pair [a, b] means "to take a you must first take b". Return true if you can finish every course, i.e. the requirements never go round in a circle (a needs b, b needs a).

Do this one timed. Open one hint, try again, then open the next.

Hint 1

Count each course's in-degree: how many courses it is still waiting for.

Hint 2

Courses with in-degree 0 can be taken now. Put them in a queue.

Hint 3

When you take a course, every course that depended on it has one less thing to wait for. If that drops to 0, it joins the queue. If you take all numCourses, there was no cycle.

Show the full walkthrough

How to think about it

Kahn's algorithm, the same code as in the cram notes. Repeatedly take any course with nothing left to wait for. Courses stuck in a cycle never reach 0, so you'll take fewer than numCourses.

The code

class Solution {
public:
    bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
        vector<vector<int>> unlocks(numCourses);  // b -> courses that need b
        vector<int> waitingFor(numCourses, 0);    // the "in-degree"

        for (auto& p : prerequisites) {
            int course = p[0], needs = p[1];
            unlocks[needs].push_back(course);
            waitingFor[course]++;
        }

        queue<int> q;                             // courses we can take now
        for (int i = 0; i < numCourses; i++)
            if (waitingFor[i] == 0) q.push(i);

        int taken = 0;
        while (!q.empty()) {
            int c = q.front();
            q.pop();
            taken++;
            for (int next : unlocks[c]) {
                waitingFor[next]--;               // one fewer to wait for
                if (waitingFor[next] == 0) q.push(next);
            }
        }
        return taken == numCourses;               // all taken = no cycle
    }
};

How fast

Time O(courses + prerequisites). Space the same.

Watch out

  • Read the pair the right way round: [a, b] means b comes before a, so the arrow goes b → a.

#16 · Easy · Binary search

Binary Search

In plain words

The list is sorted. Return the index of target, or −1 if it isn't there. Must be O(log n).

How to think about it

Like guessing a number between 1 and 100 by always guessing the middle: each guess throws away half of what's left. Keep two ends, lo and hi. Look at the middle element. If it's the target, done. If it's too small, the target can only be to the right, so move lo past mid. If it's too big, move hi before mid. Stop when lo passes hi.

Steps

  1. lo = 0, hi = n − 1.
  2. While lo ≤ hi: mid = lo + (hi − lo) / 2.
  3. nums[mid] == target → return mid. nums[mid] < target → lo = mid + 1. Otherwise hi = mid − 1.
  4. Loop ended: return −1.

The code

class Solution {
public:
    int search(vector<int>& nums, int target) {
        int lo = 0, hi = (int)nums.size() - 1;   // search inside [lo, hi]

        while (lo <= hi) {
            // Same as (lo + hi) / 2, but can't overflow for huge numbers
            int mid = lo + (hi - lo) / 2;

            if (nums[mid] == target) return mid;      // found it
            if (nums[mid] < target) lo = mid + 1;     // answer is to the right
            else hi = mid - 1;                        // answer is to the left
        }
        return -1;                                    // range is empty
    }
};

Walk through the example

05233 < 9 → lo = 3
3549found → return 4

How fast

Time O(log n): the range halves every step (a million items takes about 20 steps). Space O(1).

Watch out

  • The trace uses nums = [−1, 0, 3, 5, 9, 12], target 9.
  • Use lo + (hi − lo) / 2, not (lo + hi) / 2, so a big lo + hi can't overflow an int.
  • Off-by-one bugs are the classic mistake. In this version the range is [lo, hi] inclusive, so the loop is lo ≤ hi and you move to mid ± 1.
#17 · Easy · Binary search (lower bound)

Search Insert Position

In plain words

The list is sorted with no duplicates. Return the index of target if it's there; if not, return the index where it would be inserted to keep the list sorted. Example: [1, 3, 5, 6], target 2 → 1.

How to think about it

Both cases ask the same question: "what's the first index whose value is ≥ target?" That's called the lower bound, and it's the binary search template in the cram notes. Here the range is [lo, hi) with hi = n, because the answer can be n (insert at the very end).

Steps

  1. lo = 0, hi = n (one past the end).
  2. While lo < hi: mid = lo + (hi − lo) / 2.
  3. If nums[mid] < target, the answer is after mid: lo = mid + 1. Otherwise mid might be the answer: hi = mid.
  4. When lo == hi, that's the answer.

The code

class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        // Find the first index whose value is >= target.
        // The answer is somewhere in [lo, hi); hi = n allows "at the end".
        int lo = 0, hi = nums.size();

        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] < target) {
                lo = mid + 1;      // mid is too small, so it can't be it
            } else {
                hi = mid;          // mid could be the answer: keep it
            }
        }
        return lo;                 // lo == hi: the first index >= target
    }
};

How fast

Time O(log n), space O(1).

Watch out

  • Notice the differences from Binary Search: hi = n, lo < hi, and hi = mid (not mid − 1). Learn this one version well; it solves most "find the first ..." problems.
  • The one-liner: return lower_bound(nums.begin(), nums.end(), target) - nums.begin();
#18 · Medium · Binary search on the answer

Koko Eating Bananas

In plain words

There are piles of bananas and h hours. Each hour Koko picks one pile and eats up to k bananas from it (if the pile has fewer, she finishes it and waits for the next hour). Find the smallest speed k that lets her finish everything within h hours. Example: piles [3, 6, 7, 11], h = 8 → 4.

How to think about it

You aren't searching a list here; you're searching for the answer itself. Speeds go from 1 to the biggest pile. If speed k is fast enough, every faster speed is too. So the speeds look like: no, no, no, YES, yes, yes. Binary search finds the first YES. To test one speed k: a pile of p takes ceil(p / k) hours; add those up and compare with h.

Steps

  1. lo = 1, hi = largest pile (eating that fast always finishes in n hours).
  2. While lo < hi: try k = middle. Count the hours at speed k.
  3. If hours ≤ h, k works, but maybe a slower one does too: hi = k. Otherwise k is too slow: lo = k + 1.
  4. Return lo.

The code

class Solution {
public:
    int minEatingSpeed(vector<int>& piles, int h) {
        int lo = 1;
        int hi = *max_element(piles.begin(), piles.end());  // biggest pile

        while (lo < hi) {
            int k = lo + (hi - lo) / 2;      // the speed we're testing

            // Total hours at speed k. long long because it can get big.
            long long hours = 0;
            for (int p : piles) {
                hours += (p + k - 1) / k;    // = p / k rounded up
            }

            if (hours <= h) hi = k;          // fast enough: try slower
            else lo = k + 1;                 // too slow: must go faster
        }
        return lo;                           // the slowest speed that works
    }
};

How fast

Time O(n log m), where m is the biggest pile: about 30 guesses, each one a pass over the piles. Space O(1).

Watch out

  • (p + k − 1) / k is the integer trick for rounding up. 7 bananas at speed 3: (7 + 2) / 3 = 3 hours.
  • *max_element(...) returns an iterator; the * reads the value it points to.
  • Look for this pattern whenever a problem says "find the minimum X such that ..." and bigger X always works.
#19 · Medium · Sort, then sweep

Merge Intervals

In plain words

Each interval is [start, end]. Merge every group of overlapping intervals into one. Example: [[1,3],[2,6],[8,10],[15,18]] → [[1,6],[8,10],[15,18]], because [1,3] and [2,6] overlap.

How to think about it

Sort the intervals by their start. Now overlapping ones are next to each other. Walk through them with an answer list: if the current interval starts after the last merged one ends, it's separate, so add it. Otherwise it overlaps, so stretch the last merged interval's end to cover it.

Steps

  1. Sort the intervals (a vector of vectors sorts by the first number, then the second).
  2. For each interval cur: if the answer is empty or answer.back()[1] < cur[0], push cur.
  3. Else set answer.back()[1] = max(answer.back()[1], cur[1]).

The code

class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {
        sort(intervals.begin(), intervals.end());   // by start time

        vector<vector<int>> merged;
        for (auto& cur : intervals) {
            // No overlap: the last merged interval ends before cur starts
            if (merged.empty() || merged.back()[1] < cur[0]) {
                merged.push_back(cur);
            } else {
                // Overlap: extend the last one. max() handles an interval
                // completely inside another, like [1,10] then [2,3].
                merged.back()[1] = max(merged.back()[1], cur[1]);
            }
        }
        return merged;
    }
};

How fast

Time O(n log n) for the sort, then O(n). Space O(n) for the answer.

Watch out

  • .back() is the last element of a vector. merged.back()[1] is the end of the last merged interval.
  • [1,4] and [4,5] count as overlapping here (they touch), which is why the test is < and not ≤.
#20 · Medium · Greedy: sort by end

Non-overlapping Intervals

In plain words

Return the fewest intervals you must remove so the rest don't overlap. Touching is allowed: [1,2] and [2,3] don't overlap. Example: [[1,2],[2,3],[3,4],[1,3]] → 1 (remove [1,3]).

How to think about it

Flip the question: keep as many intervals as possible. The greedy rule that works is to always keep the interval that ends earliest, because it leaves the most room for the rest. So sort by end time, keep the first, then keep each next interval only if it starts at or after the end of the last one you kept. Everything you skip is a removal.

Steps

  1. Sort by end time (use a custom comparison).
  2. lastEnd = end of the first interval; removed = 0.
  3. For each following interval: if its start ≥ lastEnd, keep it (lastEnd = its end). Otherwise removed++.
  4. Return removed.

The code

class Solution {
public:
    int eraseOverlapIntervals(vector<vector<int>>& intervals) {
        // Sort by END time. The lambda says "a goes before b if a ends first".
        sort(intervals.begin(), intervals.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[1] < b[1];
             });

        int removed = 0;
        int lastEnd = intervals[0][1];          // we keep the first one

        for (int i = 1; i < (int)intervals.size(); i++) {
            if (intervals[i][0] >= lastEnd) {
                lastEnd = intervals[i][1];      // no overlap: keep it
            } else {
                removed++;                      // overlaps: remove it
            }
        }
        return removed;
    }
};

How fast

Time O(n log n), space O(1) extra (apart from the sort).

Watch out

  • The [](...) { ... } part is a lambda: a small unnamed function you pass to sort to say how to compare two items. It must return true when a should come before b.
  • Sorting by start instead of end gives wrong answers on cases like [[1,100],[2,3],[4,5]].

In plain words

Write a class for a car park with a fixed number of big, medium and small spaces. addCar(carType) (1 = big, 2 = medium, 3 = small) parks the car and returns true if a space of that size is free, otherwise returns false.

class ParkingSystem {

Find Minimum in Rotated Sorted Array

In plain words

A sorted list was "rotated": some of the front moved to the back, e.g. [0,1,2,4,5,6,7] became [4,5,6,7,0,1,2]. All values are different. Find the smallest value in O(log n).

Do this one timed. Open one hint, try again, then open the next.

Hint 1

The list is two sorted runs: [4,5,6,7] then [0,1,2]. The minimum is where the second run starts.

Hint 2

Compare nums[mid] with nums[hi] (the last element of the range). If nums[mid] > nums[hi], the drop is to the right of mid.

Hint 3

Otherwise mid could be the minimum, so keep it: hi = mid. Use the lo < hi template from Search Insert Position.

Show the full walkthrough

How to think about it

Binary search, but the question at mid is "is mid in the left (bigger) run?". If nums[mid] > nums[hi], yes, so the minimum is after mid. If not, mid is in the right run, so the minimum is mid or before it.

The code

class Solution {
public:
    int findMin(vector<int>& nums) {
        int lo = 0, hi = (int)nums.size() - 1;

        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] > nums[hi]) {
                // mid is in the left, bigger run: the drop is after mid
                lo = mid + 1;
            } else {
                // mid is in the right, smaller run: min is mid or earlier
                hi = mid;
            }
        }
        return nums[lo];       // lo == hi: the smallest value
    }
};

How fast

Time O(log n), space O(1).

  • Compare with nums[hi], not nums[lo]. Comparing with nums[lo] fails when the list isn't rotated at all, like [1,2,3].

Show the full walkthrough

How to think about it

The code

#include <bits/stdc++.h>
using namespace std;

struct Book {              // a struct is a class whose members are public
    string title;
    string author;
    int year;
};

class Library {
private:
    unordered_map<int, Book> books;          // id -> Book

public:
    void addBook(int id, string title, string author, int year) {
        books[id] = {title, author, year};   // ids are unique
    }

    bool removeBook(int id) {
        // erase(key) returns how many it removed: 1 or 0
        return books.erase(id) == 1;
    }

    vector<string> findByAuthor(string author) {
        vector<Book> mine;
        for (auto& [id, b] : books) {
            if (b.author == author) mine.push_back(b);
        }
        // Oldest first; if two have the same year, A to Z by title
        sort(mine.begin(), mine.end(), [](const Book& a, const Book& b) {
            if (a.year != b.year) return a.year < b.year;
            return a.title < b.title;
        });
        vector<string> titles;
        for (auto& b : mine) titles.push_back(b.title);
        return titles;
    }

    int countPublishedAfter(int year) {
        int count = 0;
        for (auto& [id, b] : books) {
            if (b.year > year) count++;      // strictly greater
        }
        return count;
    }
};

int main() {
    Library lib;
    lib.addBook(1, "Dune", "Herbert", 1965);
    lib.addBook(2, "Emma", "Austen", 1815);
    lib.addBook(3, "Persuasion", "Austen", 1817);
    lib.addBook(4, "Children of Dune", "Herbert", 1976);

    for (auto& t : lib.findByAuthor("Austen")) cout << t << '\n';
    cout << lib.countPublishedAfter(1900) << '\n';   // 2
    cout << boolalpha << lib.removeBook(1) << '\n';  // true
    cout << lib.removeBook(1) << '\n';               // false
    cout << lib.countPublishedAfter(1900) << '\n';   // 1
    return 0;
}

How fast

addBook and removeBook O(1). findByAuthor O(n + m log m), where m is that author's books. countPublishedAfter O(n).

Watch out

  • boolalpha makes cout print true/false instead of 1/0.
  • Follow-up answers: to make countPublishedAfter fast, keep a map<int, int> of year → count, or a sorted vector of years plus upper_bound, giving O(log n). To make findByAuthor fast, also keep unordered_map<string, set<pair<int, string>>> from author to (year, title), which is always sorted.

#24 · Easy · DP: count the ways

Climbing Stairs

In plain words

There are n steps. Each move you climb 1 or 2 steps. How many different ways can you reach the top? Example: n = 3 → 3 (1+1+1, 1+2, 2+1).

How to think about it

This is the gentlest DP problem. Think about the last move. To stand on step i, you came either from step i−1 (a 1-step) or from step i−2 (a 2-step). So ways(i) = ways(i−1) + ways(i−2). Fill that in from the bottom. You only ever need the previous two values, so two variables are enough.

Steps

  1. State: ways(i) = number of ways to reach step i.
  2. Base: ways(1) = 1, ways(2) = 2.
  3. Transition: ways(i) = ways(i−1) + ways(i−2).
  4. Answer: ways(n).

The code

class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) return n;          // 1 step: 1 way; 2 steps: 2 ways

        int twoBack = 1;               // ways to reach step i-2 (step 1)
        int oneBack = 2;               // ways to reach step i-1 (step 2)

        for (int i = 3; i <= n; i++) {
            int current = oneBack + twoBack;   // came from i-1 or i-2
            twoBack = oneBack;                 // slide the window forward
            oneBack = current;
        }
        return oneBack;                // ways to reach step n
    }
};

#25 · Easy · DP: minimum cost

Min Cost Climbing Stairs

In plain words

cost[i] is what you pay to step on step i. You can start on step 0 or 1, and each move goes up 1 or 2. The top is just past the last step. Return the cheapest total. Example: cost = [10, 15, 20] → 15 (start on step 1, pay 15, jump 2 to the top).

How to think about it

Same shape as Climbing Stairs, but instead of adding the ways you take the cheaper option. dp[i] = the cheapest total to stand on step i = cost[i] + the cheaper of dp[i−1] and dp[i−2]. The top can be reached from either of the last two steps, so the answer is the smaller of those two.

Steps

  1. dp[0] = cost[0], dp[1] = cost[1] (you can start on either).
  2. For i ≥ 2: dp[i] = cost[i] + min(dp[i−1], dp[i−2]).
  3. Answer: min(dp[n−1], dp[n−2]).

The code

class Solution {
public:
    int minCostClimbingStairs(vector<int>& cost) {
        int n = cost.size();
        // dp[i] = cheapest total to be standing on step i
        vector<int> dp(n);
        dp[0] = cost[0];               // start on step 0
        dp[1] = cost[1];               // or start on step 1

        for (int i = 2; i < n; i++) {
            // Came from one step below or two steps below; take the cheaper
            dp[i] = cost[i] + min(dp[i - 1], dp[i - 2]);
        }
        // The top is reached from the last step or the one before it
        return min(dp[n - 1], dp[n - 2]);
    }
};

How fast

Time O(n), space O(n). It can be O(1) with two variables, like Climbing Stairs.

Watch out

  • The top is not step n−1, it's one past it. That's why the answer is a min of the last two.
#26 · Medium · DP: take or skip

House Robber

In plain words

Houses in a row hold nums[i] money. You can't rob two houses next to each other. Return the most money you can get. Example: [2, 7, 9, 3, 1] → 12 (houses 0, 2 and 4: 2 + 9 + 1).

How to think about it

At each house you choose: rob it (then you couldn't rob the previous one, so add it to the best up to two houses back) or skip it (keep the best up to the previous house). best(i) = max(best(i−1), best(i−2) + nums[i]). Like Climbing Stairs, you only need the last two values.

Steps

  1. State: best(i) = most money from houses 0..i.
  2. Transition: max(skip = best(i−1), rob = best(i−2) + nums[i]).
  3. Start with both "previous" values at 0 and walk through the houses.
  4. Answer: best of the last house.

The code

class Solution {
public:
    int rob(vector<int>& nums) {
        int twoBack = 0;   // best total up to the house two before this one
        int oneBack = 0;   // best total up to the previous house

        for (int money : nums) {
            int robIt  = twoBack + money;   // rob this: previous must be safe
            int skipIt = oneBack;           // skip this: keep previous best
            int best = max(robIt, skipIt);

            twoBack = oneBack;              // move forward one house
            oneBack = best;
        }
        return oneBack;
    }
};

#27 · Medium · DP: minimum over choices

Coin Change

In plain words

Given coin values (unlimited of each) and an amount, return the fewest coins that add up to exactly the amount, or −1 if it can't be done. Example: coins [1, 2, 5], amount 11 → 3 (5 + 5 + 1).

How to think about it

Build up answers for every amount from 0 to the target. dp[a] = fewest coins to make a. To make a, the last coin you used was some coin c, so you needed dp[a − c] coins before it, plus 1. Try every coin and take the smallest. Amounts you can't make stay at a big "impossible" value.

Steps

  1. dp has amount + 1 slots, all set to a huge number (impossible). dp[0] = 0 (zero coins make 0).
  2. For a = 1 to amount, for each coin c ≤ a: if dp[a − c] is possible, dp[a] = min(dp[a], dp[a − c] + 1).
  3. If dp[amount] is still huge, return −1, else dp[amount].

The code

class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        const int IMPOSSIBLE = amount + 1;   // more coins than could ever
                                             // be needed, so it means "can't"
        // dp[a] = fewest coins to make amount a
        vector<int> dp(amount + 1, IMPOSSIBLE);
        dp[0] = 0;                           // 0 needs no coins

        for (int a = 1; a <= amount; a++) {
            for (int c : coins) {
                if (c <= a && dp[a - c] != IMPOSSIBLE) {
                    // Use coin c last: make (a - c), then add this coin
                    dp[a] = min(dp[a], dp[a - c] + 1);
                }
            }
        }
        return dp[amount] == IMPOSSIBLE ? -1 : dp[amount];
    }
};

How fast

Time O(amount × number of coins). Space O(amount).

Watch out

  • Greedy (always take the biggest coin) is wrong. Coins [1, 3, 4], amount 6: greedy gives 4+1+1 = 3 coins, but 3+3 = 2 coins.
  • Using amount + 1 as "impossible" instead of INT_MAX avoids overflow when you add 1 to it.
  • x ? y : z means "if x then y else z".
#28 · Medium · DP on a grid

Unique Paths

In plain words

A robot starts at the top-left of an m × n grid and can only move right or down. How many different paths reach the bottom-right? Example: m = 3, n = 7 → 28.

How to think about it

To reach a cell, the robot came from the cell above or the cell to the left. So paths(r, c) = paths(r−1, c) + paths(r, c−1). Every cell in the top row and the left column has exactly 1 path (keep going straight). Fill the grid row by row.

Steps

  1. Make an m × n grid filled with 1 (this covers the top row and left column).
  2. For r from 1 and c from 1: dp[r][c] = dp[r−1][c] + dp[r][c−1].
  3. Answer: dp[m−1][n−1].

The code

class Solution {
public:
    int uniquePaths(int m, int n) {
        // dp[r][c] = number of paths to reach (r, c).
        // Start everything at 1: the top row and left column only have one
        // path each (all right, or all down).
        vector<vector<int>> dp(m, vector<int>(n, 1));

        for (int r = 1; r < m; r++) {
            for (int c = 1; c < n; c++) {
                // Arrived from above or from the left
                dp[r][c] = dp[r - 1][c] + dp[r][c - 1];
            }
        }
        return dp[m - 1][n - 1];
    }
};

How fast

Time O(m × n), space O(m × n). One row is enough if you want O(n) space.

Watch out

  • vector<vector<int>> dp(m, vector<int>(n, 1)) reads as: m rows, each row is n ints set to 1.

Ransom Note

In plain words

Can you build the string ransomNote by cutting letters out of magazine? Each magazine letter can be used once. Lowercase letters only. Example: "aa" from "aab" → true; "aa" from "ab" → false.

Do this one timed. Open one hint, try again, then open the next.

Hint 1

Same counting trick as Valid Anagram: an array of 26 counters.

Hint 2

Count the magazine's letters first. Then go through the note and take letters away.

Hint 3

If any counter goes below 0, the magazine didn't have enough of that letter.

Show the full walkthrough

How to think about it

Count what the magazine offers, then spend from it for each letter in the note. Going negative means you ran out.

The code

class Solution {
public:
    bool canConstruct(string ransomNote, string magazine) {
        int have[26] = {0};
        for (char c : magazine) have[c - 'a']++;    // letters available

        for (char c : ransomNote) {
            have[c - 'a']--;                        // use one
            if (have[c - 'a'] < 0) return false;    // didn't have enough
        }
        return true;
    }
};

How fast

Time O(note + magazine), space O(1).

Watch out

  • Count the magazine first, not the note.
#30 · Medium · Connected parts of a graph · Mock

Number of Provinces

In plain words

There are n cities. isConnected[i][j] = 1 means city i and city j are directly connected. A province is a group of cities connected directly or through others. Count the provinces.

Do this one timed. Open one hint, try again, then open the next.

Hint 1

This is Number of Islands on a graph instead of a grid.

Hint 2

The neighbours of city u are every j where isConnected[u][j] == 1.

Hint 3

Loop over cities; each unvisited one starts a new province. Visit everything reachable from it (DFS), then carry on.

Show the full walkthrough

How to think about it

Count connected components. For each city not yet visited, add 1 and visit everything you can reach from it.

The code

class Solution {
public:
    int findCircleNum(vector<vector<int>>& isConnected) {
        int n = isConnected.size();
        vector<bool> visited(n, false);
        int provinces = 0;

        for (int i = 0; i < n; i++) {
            if (!visited[i]) {          // a city in a new province
                provinces++;
                visit(isConnected, visited, i);
            }
        }
        return provinces;
    }

private:
    // Mark u and every city reachable from it as visited
    void visit(vector<vector<int>>& g, vector<bool>& visited, int u) {
        visited[u] = true;
        for (int v = 0; v < (int)g.size(); v++) {
            if (g[u][v] == 1 && !visited[v]) {
                visit(g, visited, v);
            }
        }
    }
};

How fast

Time O(n²): the matrix has n² entries. Space O(n).

Watch out

  • Pass visited by reference (&). Without the &, each call gets its own copy and the marks are lost.
#31 · Medium · DP: best ending here · Mock

Longest Increasing Subsequence

In plain words

Return the length of the longest strictly increasing subsequence. A subsequence keeps the order but can skip elements. Example: [10, 9, 2, 5, 3, 7, 101, 18] → 4 (2, 3, 7, 101).

Do this one timed. Open one hint, try again, then open the next.

Hint 1

State: dp[i] = length of the longest increasing subsequence that ends at index i.

Hint 2

To end at i, the previous element is some j < i with nums[j] < nums[i]. So dp[i] = 1 + the biggest such dp[j] (or just 1 if there's none).

Hint 3

The answer is the largest value anywhere in dp, not necessarily dp[n − 1].

Show the full walkthrough

How to think about it

For each position, look back at every earlier, smaller element and extend the best run ending there. Two loops, O(n²), which is enough for n ≤ 2,500.

The code

class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        int n = nums.size();
        // dp[i] = longest increasing subsequence that ENDS at index i.
        // Every element alone is a subsequence of length 1.
        vector<int> dp(n, 1);
        int best = 1;

        for (int i = 1; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    // Put nums[i] after the best run that ends at j
                    dp[i] = max(dp[i], dp[j] + 1);
                }
            }
            best = max(best, dp[i]);
        }
        return best;
    }
};

How fast

Time O(n²), space O(n).

Watch out

  • Follow-up for O(n log n): keep a vector tails; for each x, lower_bound it in tails and replace that element (or push_back if x is bigger than all). The answer is tails.size().
